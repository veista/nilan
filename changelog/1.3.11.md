# 1.3.11 (14/08/2026)

**Title:** Non-blocking setup + multi-unit unique IDs

**Tag:** [v1.3.11](https://github.com/master3395/veista-nilan/releases/tag/v1.3.11)  
**Author:** master3395

## What changed

- Modbus connect during setup is limited to **15 seconds**. If the unit is unreachable, setup raises ``ConfigEntryNotReady`` and Home Assistant continues starting; the entry retries later instead of waiting forever on ``event_connected``.
- Hub is closed on connect timeout / setup failure so background Modbus reconnect does not linger.
- Entity ``unique_id`` values are hub-scoped (`nilan_hub_<entry_id>_…`) so two config entries no longer collide (`ID hvac already exists`). Includes registry migration from bare ids.
- Device registry identifiers use the same hub id (with migration from `name+type`) so multi-unit installs stay separate devices.
- Removed hardcoded ``suggested_area: "Boiler Room"`` so entity id prefixes follow the configured device name.

## Operator notes

- After upgrade, restart HA (or reload Nilan). With the Nilan powered off or unreachable, HA should finish startup within ~15s for this integration and show Nilan as retrying.
- Existing single-unit installs: entity history should stay attached via unique_id migration. If you see duplicates, remove orphaned entities once.
